2. **확인 집합(평가 B)은 "결함 줄에서 mutant가 더 많이 살아남는다"는 가설을 지지하지 않았다.**

3. **이번 연산자 집합(기존 토큰 바꾸기)은 빠진 조건·실행 조건형 결함을 직접 겨냥하기 어렵다.** 확인된 결함 3줄 중 2줄이 이런 유형이다.

**지금 말할 수 있는 것**:
- 지지됨: mutation은 **기존 검증 공백 보고서가 표시하지 않은 줄**에서, 보강할 수 있는 테스트 부족을 찾는다.
- 지지 안 됨: mutation이 결함 위치를 알려준다.

## 7. 그 밖에 발견한 것

- **"covered"의 정의가 두 가지다.** coverage의 테스트 context는 여러 줄짜리 문장의 이어지는 줄(C1 `manual.py:42`, #23 `account_map.py:40`)도 실행됐다고 기록한다. ReleaseGuard의 줄 상태는 문장 시작 줄 기준이라 `not_executable`로 본다. mutation 대상을 고를 때와 보고서를 쓸 때 기준을 하나로 맞춰야 한다.
- YAML의 `no:` 키가 불리언 `false`로 읽혀 실행 스크립트가 한 번 멈췄다. `mutant:`로 이름만 바꿨고 분류 내용은 그대로다. 평가 B는 다시 실행했다.
