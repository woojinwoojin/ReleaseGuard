## 1. 결론

1. **잘못된 SAFE를 막는 동작은 확인됐다. 다만 심은 사례와 통합 테스트에서만이다.**
   - 경계 사례: 테스트 전부 skip, 테스트 전부 삭제가 SAFE → REVIEW(T03)로 바뀌었다.
   - Predict 심은 사례: T03 4/4, 반례 3/3.
   - 반례 통합 테스트: X1~X12, D1~D3 모두 기대대로다.
   - **실제 58커밋에서는 이전에 SAFE였다가 바뀐 커밋이 0개다.** #11에서 본 대로 이 경계 입력이 시험장 이력에 없었기 때문이다. 실제 데이터에서 효과를 확인한 것은 아니다.
2. **부작용은 관찰되지 않았다.**
   - 58커밋 판정 변화: 0
   - 과잉 경고: 11/19, 코드 변경만 보면 11/12로 그대로
   - T03은 7개 커밋에 붙었지만 모두 이미 REVIEW나 BLOCK이었다.
3. **실제 데이터의 T03 7건은 모두 맞는 관찰이고, 원인은 하나다.** week1·week3의 `tests/test_app.py` UI 테스트는 gitignore된 `data/`가 없어 skip된다. 보고서 #4에서 본 문제이고, 4주차 `abe0ad4`에서 사람이 고쳤다. v3.1에서는 이 사실이 skip 표에만 있었는데, 이제 판정 근거에 나온다.
4. 판정 구분력(Decision Utility)은 이 단계의 목표가 아니었고 바뀌지 않았다.

## 2. 바뀐 것

| 항목 | 내용 |
|---|---|
| T03 (REVIEW) | 바뀐 테스트가 이번 실행에서 실행되지 않음. 원인 코드 4개: `NO_TEST_RESULTS` · `CHANGED_TESTS_ALL_SKIPPED` · `MODULE_SKIPPED` · `TEST_SUITE_REMOVED` (`changed_tests.py`) |
| N07 (NOTE) | pytest 수집 설정을 지원하지 않아 T03의 앞 세 검사를 보류함 |
| N06 메시지 | "테스트가 지나가지 않는 경로의 참조는 확인하지 않음 (삭제 영향 미검증)" 추가 |
| scope | 그대로. `COMPLETE`와 T03이 함께 나올 수 있다는 설명을 보고서에 추가 |
| coverage 도구 | 실행 전에 실제로 import되는 coverage·pytest-cov의 버전과 `.rg/tools` 안인지 확인. 맞지 않으면 재설치 1회, 그래도 맞지 않으면 `not_run` → E01. `record.coverage_runtime`에 기록 |
| node id | `test_run.nodeid_map` = 함수 단위 id → 원본 node id (parametrize 값 포함, coverage context 기준) |
| 결과 JSON | `test_change_checks` (상태·testpaths·미지원 설정·보류한 검사·원인별 상세·결과 없는 바뀐 테스트) |

**설계 리뷰에서 바꾼 점**:
- `COLLECTION_EMPTY`를 `NO_TEST_RESULTS`로 바꿨다. JUnit에 결과가 없다는 관찰을 "수집 안 됨"으로 단정하지 않기 위해서다.
- 모듈 수준 skip을 `MODULE_SKIPPED`로 분리했다. pytest 9.1.1의 JUnit에서 함수별 결과 없이 `classname=""` 한 줄로 남는 것을 확인했다.
- 테스트 함수가 정의되지 않은 `test_*.py`(헬퍼 파일)는 대상에서 뺐다.
- 미지원 수집 설정에서는 판단을 보류한다.
- 시험장 6개 저장소가 모두 쓰는 `testpaths`는 지원한다. 미지원으로 보류했다면 모든 커밋에서 T03이 보류됐을 것이다.

## 7. 한계

- **실제 데이터에서 효과를 확인하지 못했다.** 잘못된 SAFE를 고친 실제 커밋이 0개다. 일반화하려면 이 경계 입력이 있는 독립 저장소가 필요하다.
- **삭제만 있는 테스트 함수 변경은 "바뀐 테스트 함수"로 보지 않는다.** 추가된 줄만 보기 때문이다. 예: assert 줄 삭제.
- **"원래 skip이던 것"을 구분하지 않는다** (Q2). week3처럼 같은 원인이 반복된다.
- 모듈 수준 skip의 JUnit 표현은 pytest 9.1.1에서만 확인했다.
- pytest 설정은 저장소 루트의 설정 파일만 읽는다. `rootdir`·`-c` 지정과 하위 폴더 설정 파일은 보지 않는다.
- 미지원 설정 감지는 목록 기반이다. 플러그인(`-p`)이나 `pytest_generate_tests`처럼 목록에 없는 방식으로 수집을 바꾸면 놓친다.
- D3(실행되지 않는 경로의 삭제 참조)은 SAFE로 남는다 (결정).
