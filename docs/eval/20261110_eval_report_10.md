## 1. 결론

에이전트가 쓴 테스트 제안 가운데 바로 쓰기 어려운 것을, LLM을 다시 부르지 않고 이유와 함께 표시할 수 있게 됐다.

- 저장된 응답 32개에서 N3·B1의 skip 파일 제안 8/8과 N3 실험 2의 같은 이름 제안 2/2를 잡았다.
- 겹치지 않는 제안은 모두 PASS였다. F2의 경고 4개는 의도한 결과다 (3장).
- 58커밋 판정 변화 0. 이 검증기는 판정에 들어가지 않는다.

이 규칙은 위 사례들을 보고 만들었다. 그래서 이 결과는 **회귀 확인이지 일반화 평가가 아니다.** 반례는 단위 테스트로 따로 확인했다.

## 2. 규칙

`releaseguard/suggestion_checks.py`. `analyze`에서 에이전트 설명이 끝난 뒤 돌고, 판정·findings·scope를 건드리지 않는다. 원래 제안(`suggested_test`)은 그대로 두고 `proposal_checks`를 따로 붙인다. `agent.py`의 프롬프트와 도구 루프는 바꾸지 않았다 (Stage 1.6 기준선과 비교 가능).

| 코드 | 조건 | 수준 | 입력 |
|---|---|---|---|
| S01 SKIPPED_TARGET_FILE | 제안 파일에서 이번 실행에 skip된 테스트가 있음 | 경고 | `test_run.skipped`, 파일별 테스트 수 |
| S02 SKIP_CAUSE_UNVERIFIED | 그 skip의 원인을 스냅샷에서 확인하지 못함 | 확인 필요 | skip 사유, head 파일 목록 |
| S03 TEST_NAME_COLLISION | 같은 범위에 같은 이름의 테스트 함수가 있음 | 경고 (범위가 불확실하면 후보) | head의 테스트 파일 AST |

- S01은 "실행되지 않는다"고 단정하지 않는다. "파일의 기존 테스트 n개 중 k개가 건너뛰어졌습니다. 새 테스트가 실행될지 확인하세요."라고만 쓴다.
- skip 원인 상태는 두 축이다.
  - 사유: `REASON_REPORTED`(사유 있음) / `REASON_MISSING`(사유 없음)
  - 원인: `CAUSE_CORRELATED` / `CAUSE_UNVERIFIED`. `CAUSE_CORRELATED`는 사유에 나온 경로(`data/`, `x.csv` 등)가 head 스냅샷에 없다는 뜻이다. 관련 증거일 뿐 원인을 확정하지는 않는다.
- S03:
  - 소속 클래스가 적혀 있고(`TestA::test_x`) 그 범위에 같은 이름이 있으면 확정이다.
  - 소속이 없고 모듈 수준에 같은 이름이 있으면 확정이다.
  - 같은 이름이 클래스 안에만 있으면 후보다.
  - 주석·문자열·함수 안의 함수는 세지 않는다.
- status:
  - WARN: 경고가 있음
  - UNKNOWN: 못 한 검사가 있음 (테스트를 실행하지 않았거나 파일 파싱 실패)
  - PASS: **구현된 정적 검사에서 경고가 없다**는 뜻일 뿐, 테스트가 유효하다는 뜻은 아니다.

| S03 확정 | 0 | 2 (N3 두 번 모두) |

사례별:

- **N3·B1** (week3 `tests/test_app.py`): 파일의 테스트가 전부 skip됐다 (N3 7/7, B1 5/5). 사유는 "기본 데이터(data/) 없음"이고, `data/`는 스냅샷에 없어 `CAUSE_CORRELATED`다. 실험 2의 N3은 기존 `test_unverified_evidence_is_marked`와 이름이 같아 S03 확정이다.
- **F2** (predict `tests/test_market.py`): 20개 중 1개만 skip됐다. 이 파일에 넣은 실험 2 F2 실행 1의 제안은 Gap Closure에서 실제로 실행돼 17/17줄을 메웠다 (보고서 #9). S01을 단정형으로 썼다면 이 경우는 틀렸을 것이다. "n개 중 k개"를 근거에 넣은 이유다.
- **실험 1의 N3 중복은 잡지 못한다.** 보고서 #8의 "기존 테스트와 겹침 2/2"는 이름이 아니라 내용이 겹친 것이다 (`test_unverified_evidence_adds_warning_note`). S03은 이름 충돌만 본다. 내용 중복은 여전히 사람이 판단해야 한다.
- S02는 이번 자료에서 한 번도 나오지 않았다. skip 사유 3종이 모두 스냅샷에서 빠진 경로를 말했기 때문이다. 사유가 없거나 경로가 없는 skip은 단위 테스트로만 확인했다.
- 두 번 재실행했을 때 경고 코드가 같았다.

## 5. 역할 구분

| 검사 | 담당 |

| 파일·줄·도구 참조가 존재하는지 | `references_valid` (기존) |
| 테스트 제안의 구조적 충돌 (skip 파일, 같은 이름) | 이번 검증기 |

| 테스트가 공백을 메우는지 | 실제 실행 (Gap Closure) |

## 6. 하지 않은 것과 한계

- 하지 않은 것: LLM 재호출, 이름 자동 변경 같은 제안 자동 수정, skip 원인 자동 해결, 판정 규칙 변경.
- `CAUSE_CORRELATED`는 사유 문자열에 나온 경로만 본다. `skipif`의 실제 조건식은 해석하지 않는다.
- S01은 이번 실행의 skip만 본다. 다른 환경(CI, 데이터가 있는 로컬)에서는 결과가 다를 수 있다.
- "읽지 않고 인용함"(보고서 #9 6장)은 여전히 잡지 못한다. 범위만 맞으면 `references_valid`를 통과한다.
- 반례는 직접 만든 단위 테스트다. 비슷하지만 겹치지 않는 실제 에이전트 응답으로 확인한 것은 PASS 20개뿐이다.
