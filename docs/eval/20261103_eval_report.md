# Eval 보고서 #1 — 규칙 v1 + 영향 분석 에이전트

작성: 2026-11-03 · 정정: 후속 수정 커밋 수 5→6 (`da30a78` 누락), HIGH recall 0.4→0.33 · 원본 결과: [20261103_eval_agent_raw.md](20261103_eval_agent_raw.md), [20261103_eval_agent_raw.json](20261103_eval_agent_raw.json)

## 1. 요약

- **판정 정확도 0.867 (13/15)**, 과소 경고 0, 과잉 경고 2. 틀린 2건은 모두 규칙(R03·R02) 때문이고 에이전트는 판정을 바꾸지 못했다.
- **에이전트의 HIGH 위험은 SAFE 커밋 7개에서 0건** — 문서·샘플 변경에 헛경고를 내지 않았다.
- 그러나 **실제로 나중에 고쳐진 커밋 6개 중 HIGH를 낸 것은 2개(recall 0.33)**. 규칙만으로 구분하지 못하는 "진짜 위험한 변경"을 에이전트가 골라내는 힘은 아직 약하다.
- 근거 확인 비율 **0.914**. 확인되지 않은 근거는 코드 검증이 잡아냈고, 주로 `run_existing`에 테스트가 아닌 대상을 넣은 경우였다.
- 효율: 커밋당 평균 **도구 12.1회, 입력 4.7만 토큰, 14.1초**. 문서만 바뀐 커밋에서도 최대 12만 토큰을 썼다.
- 같은 커밋(`142912b`)의 이전 단독 실행과 결과가 달랐다 (HIGH 1건 → 0건, 입력 20만 → 4.4만 토큰). **반복 실행 일관성**은 아직 측정하지 않았다.

### 3.3 추천 테스트

## 5. 이번 평가의 한계

- 수기 정답 15개, 대상 저장소 1개. 숫자 하나하나의 신뢰 구간이 넓다.
- 라벨 기준을 정한 쪽이 규칙도 설계했다. 판정 정확도는 규칙과 생각이 겹친 결과일 수 있다.
- 에이전트는 커밋당 1회만 실행했다. 3.6처럼 결과가 실행마다 달라질 수 있다.
- HIGH 위험의 내용을 저장하지 않아, 위험이 "맞는 이유로" 나왔는지는 검증하지 못했다.
